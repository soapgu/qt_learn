# 0经验开发QT-序章

### QT是有一定起手难度的客户端框架

一说起QT，我的眉头就要皱起来了。虽然这个框架是真的实打实的强！主流的windows、mac 的OS、Linux GUI，安卓，iOS就没有它不能穿的系统。
兼容性强确实没得的，但是在面对各个平台的主流开发框架面前，还是会主动选择后者。

- 为什么？
- QT虽然兼容性强，但是对平台能力的特性能力针对性不强，会有一种万金油三脚猫的角色，主流开发工具学习曲线和工具非常友好，有了更顺手的兵器谁还选QT啊。

当然这也并不是QT的错，而是一种原罪，任何一家想要“通杀”的框架都没啥好下场！比如谷歌的Flutter，虽然学习曲线要比QT要好，但是还要多学一门Dart语言也是不小的负担，碰到平台专属功能，还是要写类似桥接模式去对接原生开发框架，我用你就是简化开发的，结果我还要对接原生开发系统，我还用个毛啊，我直接使用原生开发框架不就好了！

有点跑题了，拉回来，为什么QT起手学习曲线陡峭，主要有下面几点

![Qt 初学者面临的四道学习关卡](../assets/Qt起手学习曲线.png)

1. C++语言关
虽然C++语言很强大，效率很高，但是在商用领域，要快速上手、迭代、结构性好，一般会选择JAVA或者C#这种静态语言，C++直接露面的机会少，哪怕和C++配合的胶水语言python也比C++的出镜率要高得多。见得少，练习机会自然也少。一些生僻的概念比如宏定义和指针概念比较劝退，平心而论C++的语法读起来并不算太难，由于不熟悉心理上的排斥要占很大的一部分

2. 环境、IDE关
这确实是QT以及其他类似IDE的硬伤。这QtCreator的工具用起来绝对拉胯，动不动给你崩溃。配置选项复杂劝退，而且你配错了，直接闪退。完全没有主流工具默认配置的体验，要跑出一个hello world你已经客服了大量的问题才能到达的。和当年的VC6.0有的一拼，当年的VC6.0还被好评了，那普遍C++的IDE是有多差才会被好评啊！

3. 相关支持资料少
和web、JAVA、安卓主流框架比起来，QT只能算小众框架，相关学习、问题解决等相关资料就会明显少很多，你无法有足够安全感的信息量让你有信心学好QT

4. 新框架密集而又陌生的知识点
短期内会有大量新的陌生知识点，好记住和理解乃至融会贯通是一个很大的挑战

### 怎么解决问题

首先第一点，这次必须直面问题了，是一个绕不过去的问题了。以前学Qt还属于完全可学可不学，在其他平台有完全有更好用的开发平台代替，Qt完全属于“鸡肋”。但是现在国产化系统也是一个很大的市场，图形化Linux程序似乎这回到了Qt的主场了，微软好像Avalonia有这方面野心，不过好像生态也没起来，不太敢用。
我现在大致定出两条对策双管齐下，目前实验下来效果还不错

![AI Agent 辅助与跨系统客户端经验迁移两条路径汇合](../assets/Qt学习双管齐下.png)

### AI Agent辅助

现在这个年代再不使用AI Agent辅助编程属于完全落伍了。
AI Agent可以完美补齐我的短板

短板一：语言关

在“古代”我们在学校的机房打开VC6.0，编写第一个hello world的时候，能编译出几十个error！简直噩梦，现在有了Code Agent完全不会发生这样的情况，你现在完全不用写一行代码，可以轻松帮你过关编译器的检查。
当然并不是说C++语法不要学了，而是优先级被延后了，我们可以在项目中边实践边学习边强化。这仍然是我们的“技术债务”，需要我们去还的。只是有了AI以后我们完全可以先上车再补票

短板二：环境&IDE问题

有了AI以后，那些复杂的配置完全可以交给AI，对于CodeX还多了一个电脑操控，完全可以用人的角度来输入。我QtCreator的配置就是AI搞定的。有了AI加持，配置问题就不是问题了，等价于主流的开发环境的默认配置了

短板三：相关支持资料少

这个又到了AI的专长了，这个时候可以让AI化身私教，帮我定制学习资料。而且所有不明白的地方可以实时提问，虽然修改内容。不用担心问的问题是否太低级，AI会不会生气，直接打破砂锅问到底，如果还不清楚，还可以让AI把整个流程画出来，加深理解。而且这是一个性价比非常高的用法，一般都命中缓存，token的用量还特别小。

短板四：新框架密集而又陌生的知识点

这一点确实是一个问题，AI时代信息密度其实还大大提高了，要批量掌握确实难度很大，这个问题我讲会在下一个对策专门解决

### 跨系统客户端经验迁移

这是我在学安卓的时候得到的心得，安卓对我来说是一个新事物，但是WPF已经熟悉很久了。同样是客户端虽然平台有差异，但是一些经验是可以迁移的，页面的布局表达、相似布局控件、一些交互原则、异步操作的处理等等。很多都有等价物，一旦找到等价物就特别好理解了，也方便把知识体系串起来形成体系化经验。
目前发现在Qt有相当多的等价物，qml的界面表达和WPF的xaml以及安卓的xml布局文件高度同质。Qt也非常实践MVVM框架，一些Qt特别的术语翻译成WPF语言一下就豁然开朗。
而且在AI的加持下还拥有1+1>2的效果，直接一键生成跨平台类比私人定制化攻略。
如果能在项目中快速融会贯通，那么可以比以前上手速度还要快一截

### AI对比传统编程的劣势

光说优点了，劣势部分也不能说没有

- 缺少手敲代码部分，对代码阅读缺乏深度，手敲代码能方便记在心里。对于熟练代码的平台，我可以几百行上千行代码里面一扫能看出大概问题。但是对于现在的Qt代码显然心有余力不足。缺乏这份基本功

- 手敲代码，能享受到一砖一瓦搭积木的乐趣，当你看到程序成型那一刻，你能获得强烈的正反馈，状态好还能进入到心流状态。AI时代，你的这份乐趣被剥夺了，你看着AI干活少了很多代入感，程序能运行的那一刻也能感到快乐，但是不是以前那种延时满足。而接近现在这种即时快乐了

新的时代潮流已经不可阻挡，可能寻找心流状态要找寻新的方式,目前我寻找到几种方式

- 在AI代码中淘金子，在code review中找到AI代码中值得提取的经验，进一步总结成经验。形成文档

- 找到AI中代码结构的薄弱点，进行大批量重构，以一个架构师角度调解AI。特别费心力，当然得到的回报也很大。

- 想办法调解AI在计划模式磋商，最后让AI写出你完全想要写的一模一样的代码。这一种获得的正反馈也很不错，完成后review 代码也是最轻松的。不过有点难达成。
